# 実装計画

仕様の正本は [design.md](design.md) である。
この資料は、実装をどの順序で、どの単位の Issue と PR に分けるかだけを定める。

PR はスタック式に積む。
各 PR は直前の PR のブランチを土台にし、main へは前から順にマージする。

## 段階

| 段階 | 内容 | 主な完了条件 |
|---|---|---|
| 1. 基盤 | ソリューション構成、設定の読み書き(全項目と既定値)、トレイ常駐、多重起動の防止、自動起動、ログ、`UiLabels`、`build-debug.bat` と `build-release.bat` | トレイに常駐し、終了できる。設定の既定値と壊れた設定の扱いをテストで確かめる |
| 2. ホットキーと設定画面 | ホットキーの登録と失敗の通知、キー表記の解析、設定画面の全タブ | 設定画面で変えた値が保存され、ホットキーが再登録される |
| 3. 静止画 | 範囲とウィンドウの選択画面、GDI による撮影、JPEG と PNG の書き出し、クリップボード、カーソル、遅延、撮影後の動作、ファイル名のひな形、通知と効果音 | 3 種の撮影が既定の設定で保存される。PNG 書き出しとファイル名の決定をテストで確かめる |
| 4. 動画の映像 | WGC と Media Foundation による H.264 の MP4、3 種の対象、操作バー、枠、カウントダウン、一時停止、縮小、クリックの強調、エンコーダの選択 | 3 種の対象で再生できる MP4 ができる。タイムスタンプの計算をテストで確かめる |
| 5. 動画の音声 | ループバックとマイクの取得と混合、AAC、MP3(Media Foundation で扱えなければ ffmpeg を同梱) | 音声付きの MP4 が再生でき、10 分の録画で音ずれが目立たない |
| 6. 更新 | 更新の確認、更新ダイアログ、自己更新 | update.json の検証と版の比較をテストで確かめる。ローカルの update.json で更新の一連の流れが動く |
| 7. 配布 | `build-package.bat`、`tools/release-site.js`、`tools/check-manual-labels.js`、配布ページ、マニュアル、ライセンス | bat で zip、`update.json`、各ページが生成される。Node スクリプトのテストが通る |

段階 5 と 6 は互いに依存しないが、スタックを単純に保つため直列に積む。

## 実機での確認

キャプチャ、エンコード、音声、ホットキーは自動テストで確かめきれない。
各段階の PR には、実機で確かめた手順と結果を書く。
実機で確かめられなかった項目は、PR の「確認して欲しいポイント」に残す。
