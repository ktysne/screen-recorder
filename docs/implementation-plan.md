# 実装計画

仕様の正本は [design.md](design.md) である。
この資料は、実装をどの順序で、どの単位の Issue と PR に分けるかだけを定める。

PR はスタック式に積む。
各 PR は直前の PR のブランチを土台にし、main へは前から順にマージする。

## 段階

| 段階 | 内容 | 主な完了条件 |
|---|---|---|
| 1. 基盤 | ソリューション構成、設定の読み書き(全項目と既定値)、トレイ常駐、多重起動の防止、自動起動、ログ、`UiLabels`、`build-debug.bat` と `build-release.bat` | トレイに常駐し、終了できる。設定の既定値と壊れた設定の扱いをテストで確かめる |
| 2. ホットキーと設定画面 | ホットキーの登録と失敗の通知、キー表記の解析、設定画面の全タブ | 設定画面で変えた値が保存され、ホットキーが再登録される |
| 3. 静止画 | 範囲とウィンドウの選択画面、GDI による撮影、JPEG と PNG の書き出し、クリップボード、カーソル、遅延、撮影後の動作、ファイル名のひな形、通知と効果音 | 3 種の撮影が既定の設定で保存される。PNG 書き出しとファイル名の決定をテストで確かめる |
| 4. 動画の映像 | 録画エンジンの境界と ScreenRecorderLib による実装、3 種の対象(ディスプレイと範囲は Desktop Duplication、ウィンドウは WGC)、一時名と改名、操作バー、枠、カウントダウン、一時停止、縮小、クリックの強調、エンコーダの選択、ウィンドウが閉じたときの停止、スリープ時の停止 | 3 種の対象で再生できる MP4 ができる。大きさの偶数化、一時名、状態遷移をテストで確かめる |
| 5. 動画の音声 | PC の音とマイクの指定、マイクのデバイスの一覧、AAC のビットレート、ffmpeg(LGPL shared)による MP3 への変換、音声デバイスの失敗時の停止 | 音声付きの MP4 が再生できる。MP3 を選ぶと音声が MP3 の MP4 になる。変換の失敗時は AAC のまま残る |
| 6. 更新 | 更新の確認、更新ダイアログ、自己更新 | update.json の検証とバージョンの比較をテストで確かめる。ローカルの update.json で更新の一連の流れが動く |
| 7. 配布 | `build-package.bat`、`tools/release-site.js`、`tools/check-manual-labels.js`、配布ページ、マニュアル、ライセンス | bat で zip、`update.json`、各ページが生成される。Node スクリプトのテストが通る |

動画は ScreenRecorderLib を使う(採否の根拠は design.md「録画ライブラリの検証結果」)。
段階 4 は、Desktop Duplication の範囲指定(SourceRect)で範囲の録画ができることを最初に確かめる(検証では範囲を WGC でしか試していないため)。

段階 5 と 6 は互いに依存しないが、スタックを単純に保つため直列に積む。

## 実機での確認

キャプチャ、エンコード、音声、ホットキーは自動テストで確かめきれない。
各段階の PR には、実機で確かめた手順と結果を書く。
実機で確かめられなかった項目は、PR の「確認して欲しいポイント」に残す。

## 録画プロセスへの移行

録画を子プロセスへ移す変更(design.md「録画プロセス」)は、次の PR に分けてスタック式に積む。

| PR | 内容 | 主な完了条件 |
|---|---|---|
| 1. 設計 | design.md の「録画プロセス」の節と、関連する節(保存の確かさ、更新、診断ログのタグ)の更新 | 設計のレビューを終える |
| 2. やり取りの判定 | Core に置くメッセージの形と JSON、行の切り出し、本体側の受信による遷移と期限の判定、終了判定の値の追加 | 遷移と期限の性質(終端は 1 つ、完了は後の切断より優先、準備完了前の要求は順に送る、バージョンの不一致は開始の失敗、どの終わり方にも強制終了までの期限がある)をテストで確かめる。アプリの振る舞いは変えない |
| 3. 録画プロセス | `--record-worker` の起動の分岐、録画プロセス側の処理、本体側の録画エンジンの実装と差し替え、期限と強制終了、ログの転送、終了時の待ち、録画プロセスが残る間の更新の抑止 | 3 種の対象で録画が保存される。録画プロセスを止めて 2 分後に強制終了され、一時ファイルを削除でき、次の録画ができる。録画の完了から録画プロセスの終了までは更新を始められない |
| 4. 診断と周辺 | 終了コードの記録、切断後の固定名のログ、記録開始前の失敗の知らせ方 | 本体を強制終了したときに録画プロセスが書き終え、その経過が固定名のログに残る |

カウントダウン中に録画プロセスを先に起動して開始の遅れを隠す最適化は、PR 3 で開始の遅れを実測し、準備完了までの追加が 1 秒を超えるときだけ別に扱う。
