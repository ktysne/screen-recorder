# ScreenRecorder 設計

## この資料の範囲

ScreenRecorder の要件、技術選定、構成、各機能の仕様、配布と更新の仕組みを定める。
実装の順序と Issue の分け方は [implementation-plan.md](implementation-plan.md) に置く。

## 要件

ScreenRecorder は、タスクトレイに常駐する Windows 用の画面キャプチャアプリである。
トレイアイコンのメニューか、グローバルなショートカットキーから、次の 6 つの操作を行う。

- 静止画の撮影：ディスプレイ全体、指定の範囲、指定のウィンドウ
- 動画の撮影：ディスプレイ全体、指定の範囲、指定のウィンドウ

静止画の要件は次のとおり。

- 保存形式は JPEG と PNG から選べる。既定は JPEG の品質 98
- 品質を変更できる。JPEG は品質 1 から 100、PNG は圧縮の強さ(可逆なので画質は変わらない)
- 撮影と同時にクリップボードへコピーできる(設定で切り替え。既定はオン)

動画の要件は次のとおり。

- MP4 コンテナに H.264 の映像を入れる
- 画質は既定値を持ち、利用者がフレームレートとビットレートを変更できる
- PC の再生音(ループバック)を収録できる。音声形式は AAC と MP3 に対応し、既定は AAC 192 kbps
- マイク音声も収録でき、PC の再生音と混ぜて 1 本の音声にする(設定で切り替え。既定はオフ)

共通の要件は次のとおり。

- マウスカーソルを写すかどうかは、静止画と動画で別々に設定できる。既定は、静止画は写さず、動画は写す
- 保存先とショートカットキーは既定値を持ち、利用者が変更できる
- タスクトレイに常駐し、OS へのサインイン時に自動で起動する(設定で切り替え。既定はオン)
- exe を直接起動して使う。インストーラは持たない
- `build-package.bat` のダブルクリックでビルドから配布サーバへの転送までを行う
- 起動中のアプリが新しい版を通知し、通知からそのまま更新できる

表示名、exe 名、ウィンドウタイトル、設定フォルダ名は「ScreenRecorder」で統一する。
リポジトリ名と配布先のパスだけは `screen-recorder` とする。

## 技術選定

C# / .NET 10 (LTS) / WinForms を使い、自己完結の単一 exe として配布する。

選定の理由は、必要な OS 機能がすべて C# から直接呼べ、C++ より保守の手間が小さいことにある。
キャプチャ、エンコード、音声取得の重い処理は OS 側(GPU とハードウェアエンコーダ)が行うので、C# で書いても性能は落ちにくい。
UI はトレイメニュー、設定画面、範囲選択の重ね合わせ画面、録画中の操作バーだけなので、WPF ではなく軽い WinForms を選ぶ。

| 機能 | 使う仕組み |
|---|---|
| 動画のキャプチャ | Windows.Graphics.Capture(以下 **WGC**)。D3D11 のテクスチャとしてフレームを受け取る |
| 映像のエンコードと MP4 への書き込み | Media Foundation の SinkWriter。ハードウェアの H.264 エンコーダを優先し、無ければソフトウェアに切り替える |
| PC の再生音とマイク | WASAPI(ループバックとキャプチャ) |
| 静止画のキャプチャ | GDI の BitBlt(画面の該当範囲をそのまま写す) |
| JPEG の書き出し | System.Drawing の JPEG エンコーダ(品質を指定) |
| PNG の書き出し | 自前の PNG 書き出し(ZLibStream の圧縮レベルを指定するため) |

NuGet の依存は次に限る。

- **Vortice.Direct3D11 / Vortice.DXGI / Vortice.MediaFoundation**：D3D11 と Media Foundation の COM を型付きで呼ぶ
- **NAudio.Wasapi**：WASAPI のループバックとマイクの取得

対応 OS は Windows 10 2004(ビルド 19041)以降の x64 とする。
録画中の操作バーを録画に写さないために使う `WDA_EXCLUDEFROMCAPTURE` が、このビルドから使えるためである。

### MP3 音声の扱い

Media Foundation の MP4 書き込みが MP3 音声を受け付けるかどうかは、音声の段階の最初に実機で確かめる。
確かめる順は、Media Foundation の MP3 エンコーダ MFT と MP4 書き込みの組み合わせ、ffmpeg の順で、最初に通ったものを採る。
ffmpeg を使う場合は LGPL の shared ビルドを同梱し、MP3 が選ばれたときだけ使う。
その場合の流れは、映像だけの MP4 と音声の WAV を一時フォルダに書き、録画の停止後に ffmpeg で MP3 に変換して 1 本の MP4 にまとめる。
WAV は 1 時間でおよそ 700 MB になるので、録画の開始前に空き容量を確かめる。
AAC のときは ffmpeg を使わない。

## 構成

```
ScreenRecorder.slnx
src/
  ScreenRecorder.Core/    UI と OS に依存しない純粋な処理(設定、ファイル名、キー表記、更新情報の検証、PNG 書き出しなど)
  ScreenRecorder.App/     WinForms のアプリ本体(トレイ、ホットキー、キャプチャ、録画、更新)
tests/
  ScreenRecorder.Core.Tests/   xUnit
tools/                    配布サイトの生成と転送、ai-cross-review
docs/
```

Core はテストで検証できる形に保つ。
OS の API を呼ぶ処理は App に置き、判断の部分(値の検証、名前の決定、状態遷移)は Core に切り出す。

### 保存場所

- 設定：`%APPDATA%\ScreenRecorder\settings.json`
- ログ：`%LOCALAPPDATA%\ScreenRecorder\logs\`(7 日より古いものは起動時に削除)
- 更新用の一時ファイル：`%LOCALAPPDATA%\ScreenRecorder\update\`
- 静止画の既定の保存先：`ピクチャ\ScreenRecorder`
- 動画の既定の保存先：`ビデオ\ScreenRecorder`

設定ファイルが壊れていたり読めない値を含んでいたりする場合は、その項目だけ既定値に戻して起動する。
壊れたファイルは `settings.json.bak` として残す。

### 多重起動

名前付きミューテックスで 2 つ目の起動を検出し、2 つ目は何もせずに終わる。
ホットキーの登録が 2 つのプロセスで取り合いになるのを防ぐためである。

## トレイとショートカットキー

トレイアイコンのメニューは次の並びとする。

```
スクリーンショット ▸ ディスプレイ全体 / 範囲を指定 / ウィンドウを指定
録画             ▸ ディスプレイ全体 / 範囲を指定 / ウィンドウを指定
録画を一時停止/再開  (録画中だけ有効)
録画を停止         (録画中だけ有効)
─────
静止画の保存先を開く
動画の保存先を開く
─────
設定...
マニュアル
更新を確認
終了
```

メニュー項目には、割り当て中のショートカットキーを右側に表示する。

既定のショートカットキーは次のとおり。

| 操作 | 既定のキー |
|---|---|
| 静止画:範囲を指定 | PrtSc |
| 静止画:ディスプレイ全体 | Ctrl+PrtSc |
| 静止画:ウィンドウを指定 | Alt+PrtSc |
| 録画:範囲を指定 | Shift+PrtSc |
| 録画:ディスプレイ全体 | Ctrl+Shift+PrtSc |
| 録画:ウィンドウを指定 | Alt+Shift+PrtSc |

録画中に録画系のキーのどれかを押すと、録画を停止する。
静止画系のキーは録画中も静止画を撮る。

ショートカットキーは `RegisterHotKey` で登録する。
Windows 11 の「PrtSc キーで画面切り取りを開く」が有効だと PrtSc 単独の登録が失敗しうる。
登録に失敗したキーは、起動時にトレイの通知で知らせ、設定画面にも失敗の印を付ける。
PrtSc 単独の登録に失敗し、`HKCU\Control Panel\Keyboard` の `PrintScreenKeyForSnippingEnabled` が 1 のときは、OS の設定が原因だと案内し、OS のキーボード設定(`ms-settings:easeofaccess-keyboard`)を開くボタンを出す。
低レベルキーボードフックは使わない。処理が遅れると OS にフックを外され、管理者権限のアプリが前面にあるとキーを受け取れないためである。

## 撮影対象の決め方

**ディスプレイ全体**は、操作した時点でマウスカーソルがあるディスプレイを対象にする。

**範囲を指定**は、全ディスプレイを覆う重ね合わせ画面を出して、ドラッグで矩形を選ばせる。
静止画では、重ね合わせ画面を出す直前の画面を固定して表示し、その上で選ばせる(選んでいる間に画面が変わっても、見えていた内容を撮る)。
矩形は 1 つのディスプレイの中に収める。
複数ディスプレイにまたがる矩形は、ドラッグを始めたディスプレイの範囲で切り詰める。
Esc か右クリックで取り消す。

**ウィンドウを指定**は、同じ重ね合わせ画面で、カーソルの下にあるトップレベルウィンドウを枠で強調し、クリックで選ばせる。
ウィンドウの範囲は `DWMWA_EXTENDED_FRAME_BOUNDS`(影を除いた見た目の範囲)で決める。

プロセスは Per-Monitor V2 の DPI 認識で動かし(`app.manifest` で宣言する)、座標はすべて物理ピクセルで扱う。
選択画面は、ディスプレイごとに 1 枚のフォームを置き、`AutoScaleMode.None` で自前に描く。
全ディスプレイを 1 枚で覆うと、DPI の異なるディスプレイをまたいだときの自動スケーリングで座標がずれるためである。
ウィンドウの候補からは、非表示のもの、最小化されたもの、`DWMWA_CLOAKED` のもの(別の仮想デスクトップにあるウィンドウなど)を除く。

## 静止画

ディスプレイ全体と範囲は、GDI の BitBlt(`CAPTUREBLT` 付き。付けないとレイヤードウィンドウが抜ける)で画面から直接写す。
ウィンドウを指定した場合は、`PrintWindow(PW_RENDERFULLCONTENT)` で写し、前面化も Z 順の変更もしない。
結果が全面黒のとき(描画方式によって PrintWindow が内容を返さないアプリがある)は、そのウィンドウを前面に出して BitBlt で撮り直す。
HDR の表示領域は白く飛び、DRM で保護された動画は黒く写る。これは既知の制約としてマニュアルに書く。
カーソルを写す設定のときは、撮影時点のカーソルを `DrawIconEx` で描き込む。

ファイル名は設定のひな形(「設定画面」の節)から作り、同名があれば `_2`、`_3` を付ける。
動画も同じ規則で名前を付ける。
保存に成功したらトレイの通知で知らせ(設定でオフにできる)、通知のクリックで保存先のフォルダを開いてファイルを選択状態にする。

| 設定 | 値 | 既定 |
|---|---|---|
| 形式 | JPEG / PNG | JPEG |
| JPEG の品質 | 1 から 100 | 98 |
| PNG の圧縮 | 速い / 標準 / 最小サイズ | 標準 |
| クリップボードへコピー | オン / オフ | オン |
| カーソルを写す | オン / オフ | オフ |

## 動画

### 映像

3 種の対象とも WGC でフレームを受け取る。
Desktop Duplication を併用すると経路が 2 本になり、カーソルの合成(3 種の形状と XOR 合成)も自前で書くことになるためである。

フレームは D3D11 のテクスチャのまま扱い、`ID3D11VideoProcessor` で切り出し、縮小、BGRA から NV12 への変換を 1 回で行ってから、NV12 のテクスチャを Media Foundation へ渡す。
BGRA のまま渡して SinkWriter に色変換を任せると、ドライバによっては受け付けないか、ソフトウェアの変換に落ちるためである。
H.264 のエンコーダは幅と高さが偶数でないと受け付けないので、範囲、ウィンドウ、縮小後の大きさはすべて偶数に切り詰める。

映像のタイムスタンプは、フレームの番号をフレームレートで割った固定の刻みで打つ。
各刻みでは直近に届いたフレームを使い、届いていなければ前のフレームを繰り返す(WGC は画面に変化が無いとフレームを送らない)。
エンコーダが追いつかないときは、刻みを伸ばさずにフレームを落とし、落とした枚数をログに残す。

ウィンドウの録画では、WGC の `ContentSize` を大きさの正とする。
大きさが変わったらフレームプールを作り直し、録画開始時の大きさの枠に収まるように縮小して、余白を黒で埋める。
最小化中は前のフレームを繰り返す。
対象ウィンドウが閉じられたら、その時点で録画を停止して保存する。

エンコードの設定は、キーフレームの間隔 2 秒、B フレームなし、プログレッシブ、ビットレートは平均値の指定(VBR)とする。

| 設定 | 値 | 既定 |
|---|---|---|
| フレームレート | 15 / 24 / 30 / 60 fps | 30 |
| ビットレート | 1 から 100 Mbps | 12 |
| カーソルを写す | オン / オフ | オン |

WGC のカーソル表示は `GraphicsCaptureSession.IsCursorCaptureEnabled` で切り替える。
Windows 10 では WGC が録画中の対象に黄色い枠を表示する。
枠を消す `IsBorderRequired` は Windows 11 以降でしか使えないので、Windows 10 では枠が出る。

### 音声

WASAPI で PC の再生音(既定の再生デバイスのループバック)とマイクを取り、48 kHz ステレオの 32 ビット浮動小数点にそろえて混ぜる。
音声のタイムスタンプは、書き込んだサンプル数を 48000 で割って打つ。
ループバックは再生中の音が無いとデータを送らず、再生ストリームが 1 本も無いと開始もしないので、同じ再生デバイスへ無音を流し続けるストリームを録画中だけ裏で開く。
ループバックとマイクは別の時計で動くので、それぞれ 48 kHz へリサンプルしてから、10 ms ごとに混ぜる。
書き込んだサンプル数と QPC の経過時間の差が 20 ms を超えたら、無音の挿入か間引きで補正し、長時間の録画でも音ずれを溜めない。
Media Foundation の AAC エンコーダは 16 ビット整数の PCM しか受け付けないので、混ぜた後に 16 ビットへ変換する。
録画中にデバイスが外れたり既定のデバイスが切り替わったりしたら、無音で埋めながら開き直し、録画は止めない。

PC の音もマイクもオフのときは、音声トラックの無い MP4 にする。

| 設定 | 値 | 既定 |
|---|---|---|
| PC の音を収録 | オン / オフ | オン |
| マイクを収録 | オン / オフ | オフ |
| マイクのデバイス | 既定のデバイス / 一覧から選ぶ | 既定のデバイス |
| 音声形式 | AAC / MP3 | AAC |
| AAC のビットレート | 96 / 128 / 160 / 192 kbps | 192 |
| MP3 のビットレート | 128 / 192 / 256 / 320 kbps | 192 |

AAC のビットレートの選択肢は、Media Foundation の AAC エンコーダが受け付ける値に限る。

### 一時停止、カウントダウン、クリックの強調

一時停止中はフレームも音声も書かず、再開したら一時停止していた時間を差し引いてタイムスタンプを続ける。
出来上がる動画は、一時停止した区間を切り取ってつないだものになる。

カウントダウンは、対象を選び終えてから録画を始めるまでの間、画面の中央に残り秒数を出す(録画からは除く)。
カウントダウン中に停止のキーを押すと、録画を始めずに取り消す。

クリック位置の強調は、低レベルマウスフックでクリックを捉え、録画のフレームに半透明の円を描き込む。
画面上の表示は変えない。

出力の大きさが 100% 未満のときは、GPU 上で縮小してからエンコーダへ渡す。
縮小後の幅と高さも偶数に切り詰める。

### 保存の確かさ

MP4 は録画の停止時にファイルの末尾へ索引を書くので、停止の処理(SinkWriter の Finalize)が完了しないとファイルは再生できない。
録画中は `.recording.mp4` の一時名で書き、Finalize が成功したら本来の名前へ改名する。
停止の順序は、キャプチャの停止、未処理のフレームと音声の書き込み、Finalize、改名、通知とする。
停止の処理中は操作バーとトレイに「保存中」と表示する。
電源断やプロセスの強制終了では一時ファイルが再生できないまま残る。これは既知の制約としてマニュアルに書く。

録画の開始前に保存先の空き容量を確かめ、1 GB 未満なら開始せずに知らせる。
録画中に書き込みが失敗したら(ディスクが一杯になった場合など)、録画を停止して、そこまでを保存するよう試みる。
PC がスリープに入る通知を受けたら、録画を停止して保存する。

### 実装上の前提

- D3D11 のデバイスは `BGRA_SUPPORT` と `VIDEO_SUPPORT` を付けて、対象のディスプレイをつなぐアダプタで作り、`ID3D11Multithread.SetMultithreadProtected(true)` を設定する
- WinForms には DispatcherQueue が無いので、フレームプールは `Direct3D11CaptureFramePool.CreateFreeThreaded` で作る
- WGC のフレームのテクスチャはプールに戻ると上書きされるので、受け取ったらすぐ自前のテクスチャへコピーし、フレームは直ちに Dispose する
- エンコーダへ渡したテクスチャは、ハードウェアエンコーダがしばらく保持する。サンプルの返却を確かめてから使い回すか、毎回新しく作る
- Media Foundation の呼び出しは MTA の専用スレッドで行い、書き込みは上限付きのキューで受け渡す
- ハードウェアエンコーダの失敗は最初の数フレームの書き込みで表面化することがある。その場合はソフトウェアのエンコーダで作り直す
- `ICodecAPI` の設定は、入力の型を設定した後、書き込み開始の前に行う

Windows 10 では、WGC が録画中の対象に黄色い枠を表示する。
枠は録画には写らない。
Windows 11 では `IsBorderRequired` を `false` にして枠を消す(API の有無は実行時に確かめる)。

### 録画中の表示

録画中は、画面の端に経過時間、一時停止ボタン、停止ボタンを持つ小さな操作バーを出す。
範囲の録画では、録画範囲の外側に枠を出す。
操作バーと枠は `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` で録画から除く。
トレイアイコンも録画中の見た目に変える。

録画中に終了や更新を選ばれた場合は、録画を停止して保存してから進む。

## 設定画面

設定画面は次のタブで構成する。
要件の項目に加えて、この種のアプリで使われることの多い機能(遅延撮影、カウントダウン、一時停止、クリック位置の強調、ファイル名のひな形など)を入れる。

**全般**

| 設定 | 値 | 既定 |
|---|---|---|
| サインイン時に起動 | オン / オフ | オン |
| 更新を自動で確認 | オン / オフ | オン |
| 保存完了を通知 | オン / オフ | オン |
| 撮影時に効果音を鳴らす | オン / オフ | オフ |
| ファイル名のひな形 | 文字列(下記) | `ScreenRecorder_{date}_{time}` |
| 月ごとのフォルダに分ける | オン / オフ | オフ |

ファイル名のひな形では、`{date}`(yyyyMMdd)、`{time}`(HHmmss)、`{mode}`(full / region / window)、`{window}`(ウィンドウのタイトル。ファイル名に使えない文字は `_` に置き換え、40 文字で切る)を使える。
ひな形が空か、置き換え後にファイル名として使えない場合は、既定のひな形で保存する。
「月ごとのフォルダに分ける」がオンのときは、保存先の下に `yyyy-MM` のフォルダを作って保存する。

全般タブには、ログのフォルダを開くボタンと、すべての設定を既定に戻すボタンも置く。

**静止画**：保存先、形式、JPEG の品質、PNG の圧縮、クリップボードへコピー、カーソルを写す(各値は「静止画」の節)に加えて、次を置く。

| 設定 | 値 | 既定 |
|---|---|---|
| 撮影までの遅延 | なし / 3 / 5 / 10 秒 | なし |
| 撮影後の動作 | 何もしない / 既定のアプリで開く / 保存先を開く | 何もしない |

遅延は、撮影の操作をしてから(範囲やウィンドウを指定する場合は選び終えてから)撮影するまでの待ち時間である(メニューを開いた状態を撮りたい場合に使う)。
待っている間は、残り秒数を画面の端に出す(撮影からは除く)。

**動画**：保存先、フレームレート、ビットレート、カーソル、音声(各値は「動画」の節)に加えて、次を置く。

| 設定 | 値 | 既定 |
|---|---|---|
| 録画開始前のカウントダウン | なし / 3 / 5 秒 | 3 秒 |
| 出力の大きさ | 100% / 75% / 50% | 100% |
| クリック位置を強調する | オン / オフ | オフ |
| エンコーダ | 自動 / ソフトウェアのみ | 自動 |

**ショートカット**：6 つの撮影操作と「録画の一時停止/再開」(既定は割り当てなし)のキー。
入力欄でキーを押すとその組み合わせが入る。
登録に失敗したキーと、ほかの操作と重なったキーには印を付ける。

「OK」で保存して即座に反映する(ホットキーの再登録を含む)。
録画中は設定画面の動画タブを変更不可にする。

## 自動起動

`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` に `ScreenRecorder` の名前で exe のパスを書く。
設定がオンのとき、起動のたびに現在の exe のパスで書き直す(zip を別の場所へ展開し直した場合にも追従するため)。
設定をオフにしたら値を消す。

## 更新

### 最新版情報

配布サーバの `https://ktysne.info/screen-recorder/update.json` に最新版の情報を置く。

```json
{
  "schema": 1,
  "latest": {
    "version": "0.2.0",
    "url": "https://ktysne.info/screen-recorder/archives/ScreenRecorder-0.2.0-win-x64.zip",
    "sha256": "<zip の SHA-256 の 16 進 64 文字>",
    "releasedAt": "2026-10-01"
  }
}
```

アプリは次のすべてを満たす場合だけ受け付け、1 つでも外れれば「確認できなかった」として扱う。

- `schema` が整数の 1
- `latest.version` が `X.Y.Z`(各要素は数字だけ)
- `latest.url` が `https://` で始まり、ホストが `ktysne.info` と完全に一致する
- `latest.sha256` が 16 進 64 文字

ホストの比較は、`https://` の直後から最初の `/`、`?`、`#` までを取り出して一字一句比べる。
`https://ktysne.info@example.com/` のように利用者情報を挟む書き方では、実際に接続する先が後ろ側になるためである。

### 確認のタイミング

起動の 30 秒後と、その後 24 時間ごとに確認する(設定でオフにできる)。
トレイメニューの「更新を確認」からも確認でき、この場合は結果(最新です、確認できませんでした)も知らせる。

新しい版があれば、トレイの通知と更新ダイアログで知らせる。
ダイアログの選択肢は「今すぐ更新」「後で」「この版をスキップ」の 3 つとする。
スキップした版は設定に記録し、自動の確認では通知しない(手動の確認では通知する)。

### 更新の手順

1. zip を `%LOCALAPPDATA%\ScreenRecorder\update\` へダウンロードし、SHA-256 を `update.json` の値と照合する。一致しなければ中止する
2. zip を同じフォルダの下へ展開し、中に `ScreenRecorder.exe` があることを確かめる
3. 展開した新しい exe を、引数 `--apply-update <旧プロセスの PID> <展開先> <インストール先>` で起動し、旧プロセスは終了する。`--apply-update` の起動は多重起動の判定の対象外にする
4. 新しい exe は旧プロセスの終了を待ち、さらにインストール先の exe を排他で開けるようになるまで待つ(PID の再利用と、ウイルス対策ソフトによる一時的なロックがあるため。最大 30 秒、再試行付き)
5. インストール先の `ScreenRecorder.exe` を `ScreenRecorder.exe.old` へ改名してから、展開先のファイルをコピーする。コピーに失敗したら `.old` を元の名前に戻し、エラーを表示して終わる
6. 旧プロセスのミューテックスが解放されたことを確かめてから、インストール先の exe を `--updated` 付きで起動する
7. `--updated` で起動した exe は、正常に起動し終えたら `.old` を消す。起動の途中で落ちた場合に備え、更新を適用した側は 15 秒待って新しいプロセスが生きているかを確かめ、死んでいれば `.old` を戻して旧版を起動する

exe のパス(自動起動の登録にも使う)は、起動直後に 1 度だけ取得して保持する。
改名の後にパスを取り直すと `.old` のパスを登録してしまうためである。

配布する exe は単一ファイルにするが、`IncludeNativeLibrariesForSelfExtract` と圧縮は使わない。
起動のたびに一時フォルダへの展開やウイルス対策のスキャンが走って、起動が遅くなるためである。
コード署名はしない。初回の起動で SmartScreen の警告が出ることをマニュアルに書く。

録画中は更新を始めない(ダイアログの「今すぐ更新」を、録画の停止まで無効にする)。
インストール先へ書き込めない場所(Program Files など)に置かれている場合は、更新を始める前にそれを検出し、zip の手動展開を案内する。

## 配布

`build-package.bat` のダブルクリックで、次の順に進む。

1. Node.js 22.15 以降があり、`node_modules\basic-ftp` が入っていることを確かめる
2. 版(`X.Y.Z`)を尋ねる
3. 追跡中のファイルに未コミットの変更が無いことを確かめる
4. テストを実行する
5. `dotnet publish` で自己完結の単一 exe を作る
6. `index.html`(配布ページ)、`manual.html`(マニュアル)、`license.html`(ライセンス)、`update.json` を生成する
7. `ScreenRecorder-X.Y.Z-win-x64.zip` を作り、その SHA-256 を `update.json` に書く
8. 確認のうえで配布サーバへ転送する。順序は zip、`manual.html`、`license.html`、`index.html`、`update.json` の順で固定する
9. 転送できたら、ビルドしたコミットに `vX.Y.Z` のタグを付けて push する

`update.json` を最後に置くのは、通知を受けた利用者がまだ存在しない zip を取りに行く瞬間を作らないためである。

配布サーバ上の置き場は次のとおり。

- `https://ktysne.info/screen-recorder/`(`index.html`)：配布ページ
- `https://ktysne.info/screen-recorder/manual.html`：マニュアル
- `https://ktysne.info/screen-recorder/license.html`：ライセンス(本体と同梱物のライセンス表記)
- `https://ktysne.info/screen-recorder/update.json`：最新版情報
- `https://ktysne.info/screen-recorder/archives/ScreenRecorder-X.Y.Z-win-x64.zip`：配布 zip

zip の中身は `ScreenRecorder.exe`、`manual.html`、`license.html` の 3 つとする。
マニュアルとライセンスはアプリからも開けるようにする(トレイメニューの「マニュアル」と、設定画面の「ライセンス」)。
開く先は同梱の HTML で、見つからなければ配布サーバの同名のページを開く。
ffmpeg を同梱する場合は `ffmpeg\ffmpeg.exe` とそのライセンス文書を加える。

FTPS の接続情報は `tools/deploy.config.json`(Git の管理外)に置く。
雛形は `tools/deploy.config.example.json` である。

## ログ

キャプチャと録画の開始、停止、保存先、失敗の理由(HRESULT を含む)、使った GPU とエンコーダの名前、落としたフレームの数、更新の確認結果を `%LOCALAPPDATA%\ScreenRecorder\logs\` へ日ごとのファイルで書く。
利用者の操作に失敗したとき(保存できなかった、エンコーダが使えなかったなど)は、トレイの通知で理由を知らせ、詳細はログに残す。

### マニュアルとライセンスの生成

マニュアルの原稿は `site/manual.template.html`、ライセンスの原稿は `site/license.template.html`、配布ページの原稿は `site/index.template.html` に置き、`tools/release-site.js` が版を埋め込んで出力する。
UI の文言は `src/ScreenRecorder.App/UiLabels.cs` に集め、マニュアルが参照するメニュー名とボタン名がそこに実在するかを `tools/check-manual-labels.js` で検査する。
`build-package.bat` はビルドの前にこの検査を行い、食い違いがあれば止まる。
マニュアルに書いた操作が UI に無いと、利用者は手順どおりに操作できないためである。

ライセンスページには、ScreenRecorder 本体のライセンス(MIT)と、同梱するライブラリ(.NET ランタイム、Vortice.Windows、NAudio、同梱する場合は ffmpeg)のライセンス全文を載せる。
