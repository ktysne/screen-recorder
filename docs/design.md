# ScreenRecorder 設計

## この資料の範囲

ScreenRecorder の要件、技術選定、構成、各機能の仕様、配布と更新の仕組みを定める。
実装の順序と Issue の分け方は [implementation-plan.md](implementation-plan.md) に置く。

## 要件

ScreenRecorder は、タスクトレイに常駐する Windows 用の画面キャプチャアプリである。
トレイアイコンのメニューか、グローバルなショートカットキーから、次の 6 つの操作を行う。

- 静止画の撮影：ディスプレイ全体、指定の範囲、指定のウィンドウ
- 動画の撮影：ディスプレイ全体、指定の範囲、指定のウィンドウ

静止画の要件は次のとおり。

- 保存形式は JPEG と PNG から選べる。既定は JPEG の品質 98
- 品質を変更できる。JPEG は品質 1 から 100、PNG は圧縮の強さ(可逆なので画質は変わらない)
- 撮影と同時にクリップボードへコピーできる(設定で切り替え。既定はオン)

動画の要件は次のとおり。

- MP4 コンテナに H.264 の映像を入れる
- 画質は既定値を持ち、利用者がフレームレートとビットレートを変更できる
- PC の再生音(ループバック)を収録できる。音声形式は AAC と MP3 に対応し、既定は AAC 192 kbps
- マイク音声も収録でき、PC の再生音と混ぜて 1 本の音声にする(設定で切り替え。既定はオフ)

共通の要件は次のとおり。

- マウスカーソルを写すかどうかは、静止画と動画で別々に設定できる。既定は、静止画は写さず、動画は写す
- 保存先とショートカットキーは既定値を持ち、利用者が変更できる
- タスクトレイに常駐し、OS へのサインイン時に自動で起動する(設定で切り替え。既定はオン)
- exe を直接起動して使う。インストーラは持たない
- `build-package.bat` のダブルクリックでビルドから配布サーバへの転送までを行う
- 起動中のアプリが新しい版を通知し、通知からそのまま更新できる

表示名、exe 名、ウィンドウタイトル、設定フォルダ名は「ScreenRecorder」で統一する。
リポジトリ名と配布先のパスだけは `screen-recorder` とする。

## 技術選定

C# / .NET 10 (LTS) / WinForms を使い、exe と、その横に置くネイティブ DLL の組として配布する(インストーラは持たない)。

選定の理由は、必要な OS 機能と録画ライブラリが C# から直接使え、C++ より保守の手間が小さいことにある。
キャプチャ、エンコード、音声取得の重い処理は OS 側(GPU とハードウェアエンコーダ)が行うので、C# で書いても性能は落ちにくい。
UI はトレイメニュー、設定画面、範囲選択の重ね合わせ画面、録画中の操作バーだけなので、WPF ではなく軽い WinForms を選ぶ。

| 機能 | 使う仕組み |
|---|---|
| 動画の録画(キャプチャ、H.264 のエンコード、音声の取得と混合、MP4 への書き込み) | ScreenRecorderLib(MIT)。内部で Desktop Duplication、Windows.Graphics.Capture(以下 **WGC**)、Media Foundation、WASAPI を使う |
| MP3 への変換 | ffmpeg(LGPL の shared ビルド)。MP3 が選ばれたときだけ使う |
| 静止画のキャプチャ | GDI の BitBlt と PrintWindow |
| JPEG の書き出し | System.Drawing の JPEG エンコーダ(品質を指定) |
| PNG の書き出し | 自前の PNG 書き出し(ZLibStream の圧縮レベルを指定するため) |

録画を自前で書かず ScreenRecorderLib を使うのは、映像の色変換、タイムスタンプ、2 系統の音声のリサンプルと混合、ハードウェアエンコーダの失敗の扱いが、正しさを確かめにくく実機の差で壊れやすい部分であり、ライブラリがそこを引き受けるためである。
採否の根拠にした実測は「録画ライブラリの検証結果」の節に置く。

NuGet の依存は ScreenRecorderLib だけに限る。
ScreenRecorderLib は C++/CLI のアセンブリで、単一ファイルの exe には埋め込めない(埋め込むと起動時に BadImageFormatException になる)。
そのため `ScreenRecorderLib.dll` と、それが使う VC++ ランタイムの DLL(`msvcp140.dll`、`vcruntime140.dll`、`vcruntime140_1.dll`、`concrt140.dll`)を exe の横に置く。
VC++ ランタイムの exe の横への配置は、Microsoft の再頒布の条件で認められている。

対応 OS は Windows 10 2004(ビルド 19041)以降の x64 とする。
録画中の操作バーを録画に写さないために使う `WDA_EXCLUDEFROMCAPTURE` が、このビルドから使えるためである。

### 録画ライブラリの検証結果

ScreenRecorderLib 7.0.1 を、Windows 10 19045、ディスプレイ 2 台、NVIDIA GPU の PC で確かめた結果は次のとおり。

- ディスプレイ全体: Desktop Duplication では 30 fps 指定で 30 fps が出た。WGC では平均 28.5 fps で、ffmpeg がタイムスタンプの順序の警告を出した
- 範囲と縮小: 範囲を切り出し、出力の大きさを縮小できた
- ウィンドウ: WGC でほかのアプリのウィンドウを録画できた(ウィンドウの録画は WGC しか選べない)
- 一時停止と再開、状態の変化と失敗のイベント、AAC の 96 から 192 kbps、マイクの列挙: 期待どおり動いた
- PC の再生音(ループバック): 検証した PC に Windows の再生デバイスが無く、確かめられなかった

### 録画エンジンの境界

アプリは ScreenRecorderLib を直接呼ばず、録画エンジンのインターフェース(開始、一時停止、再開、停止と、状態、完了、失敗のイベント)を 1 つ置き、その実装の中でライブラリを包む。
ライブラリの未解決の不具合が実害になったときに、対象の種類ごとに別の実装へ差し替えられるようにするためである。
同じ理由で、境界は「開始の要求を送り、状態のイベントを受け取る」形にしておき、録画を子プロセス(同じ exe を `--record-worker` で起動し、名前付きパイプで結ぶ)へ移せる余地を残す。
ライブラリの異常終了はプロセスごと落ちるので、未処理例外をログに残し、次の起動時に残った一時ファイル(`.recording.mp4`)を知らせる。

### MP3 音声の扱い

MP3 が選ばれたときも、録画は ScreenRecorderLib で AAC 192 kbps の MP4 として一時名で書く。
録画の停止後に、ffmpeg で映像はそのまま(ストリームコピー)にし、音声だけを MP3(libmp3lame、設定のビットレート)に変換した MP4 を作り、元の一時ファイルを消す。
音声を別の経路で取ってまとめる方式にすると、ライブラリに任せた映像と音声の同期をアプリ側で取り直すことになるためである。
AAC から MP3 への変換は非可逆の変換を 2 度通るが、画面録画の用途では許容できる。
変換前に、元の一時ファイルと同じ大きさを目安に空き容量を確認する。
ffmpeg は exe と同じフォルダーの `ffmpeg\ffmpeg.exe` を使い、PATH は参照しない。
ffmpeg が見つからないか変換に失敗したときは、AAC のまま保存し、その旨を通知してログに標準エラーの末尾を残す。
ffmpeg が 60 秒間何も出力しなければ停止したとみなし、プロセスを終了させて AAC のまま保存する。
長い録画では変換に時間がかかるため、変換全体の時間には上限を設けない。
AAC のときは ffmpeg を使わない。

Media Foundation の MP3 エンコーダ MFT を使う経路は採らない。
検証では、MP4 へ MP3 のストリームを追加できたものの PCM の入力型の設定が失敗し、直すにはライブラリの改造が要るためである。

## 構成

```
ScreenRecorder.slnx
src/
  ScreenRecorder.Core/    UI と OS に依存しない純粋な処理(設定、ファイル名、キー表記、更新情報の検証、PNG 書き出しなど)
  ScreenRecorder.App/     WinForms のアプリ本体(トレイ、ホットキー、キャプチャ、録画、更新)
tests/
  ScreenRecorder.Core.Tests/   xUnit
tools/                    配布サイトの生成と転送、ai-cross-review
docs/
```

Core はテストで検証できる形に保つ。
OS の API を呼ぶ処理は App に置き、判断の部分(値の検証、名前の決定、状態遷移)は Core に切り出す。

### 保存場所

- 設定：`%APPDATA%\ScreenRecorder\settings.json`
- 診断ログ：`%LOCALAPPDATA%\ScreenRecorder\logs\`(直近 10 起動分。「診断ログ」の節)
- 更新用の一時ファイル：`%LOCALAPPDATA%\ScreenRecorder\update\`
- 静止画の既定の保存先：`ピクチャ\ScreenRecorder`
- 動画の既定の保存先：`ビデオ\ScreenRecorder`

設定ファイルが壊れていたり読めない値を含んでいたりする場合は、その項目だけ既定値に戻して起動する。
壊れたファイルは `settings.json.bak` として残す。

### 多重起動

名前付きミューテックスで 2 つ目の起動を検出し、2 つ目は何もせずに終わる。
ホットキーの登録が 2 つのプロセスで取り合いになるのを防ぐためである。

## トレイとショートカットキー

アプリのアイコンは `assets/screen-recorder-a1-transparent.png` の図柄で、exe、設定画面と更新ダイアログと診断ログポリシーのタイトルバー、待機中のトレイに使う。
録画の準備中は待機中のアイコンを使い、トレイの文言に「録画の準備中」と表示する。
録画中、一時停止中、保存中のトレイは、状態ごとの色と記号(赤地に丸、橙地に一時停止、灰地に時計)を塗った四角にする。
図柄にも赤い丸があるため、図柄に印を重ねる形では、小さなトレイで待機中と録画中を見分けにくいためである。

トレイアイコンのメニューは次の並びとする。

```
スクリーンショット ▸ ディスプレイ全体 / 範囲を指定 / ウィンドウを指定
録画             ▸ ディスプレイ全体 / 範囲を指定 / ウィンドウを指定
録画を一時停止/再開  (録画中と一時停止中だけ有効)
録画を停止         (カウントダウン中、準備中、録画中、一時停止中だけ有効)
─────
静止画の保存先を開く
動画の保存先を開く
─────
設定...
マニュアル
更新を確認
終了
```

メニュー項目には、割り当て中のショートカットキーを右側に表示する。

既定のショートカットキーは次のとおり。

| 操作 | 既定のキー |
|---|---|
| 静止画:範囲を指定 | PrtSc |
| 静止画:ディスプレイ全体 | Ctrl+PrtSc |
| 静止画:ウィンドウを指定 | Alt+PrtSc |
| 録画:範囲を指定 | Shift+PrtSc |
| 録画:ディスプレイ全体 | Ctrl+Shift+PrtSc |
| 録画:ウィンドウを指定 | Alt+Shift+PrtSc |

録画中に録画系のキーのどれかを押すと、録画を停止する。
静止画系のキーは録画中も静止画を撮る。

ショートカットキーは `RegisterHotKey` で登録する。
Windows 11 の「PrtSc キーで画面切り取りを開く」が有効だと PrtSc 単独の登録が失敗しうる。
登録に失敗したキーは、起動時にトレイの通知で知らせ、設定画面にも失敗の印を付ける。
PrtSc 単独の登録に失敗し、`HKCU\Control Panel\Keyboard` の `PrintScreenKeyForSnippingEnabled` が 1 のときは、OS の設定が原因だと案内し、OS のキーボード設定(`ms-settings:easeofaccess-keyboard`)を開くボタンを出す。
低レベルキーボードフックは使わない。処理が遅れると OS にフックを外され、管理者権限のアプリが前面にあるとキーを受け取れないためである。

## 撮影対象の決め方

**ディスプレイ全体**は、操作した時点でマウスカーソルがあるディスプレイを対象にする。

**範囲を指定**は、全ディスプレイを覆う重ね合わせ画面を出して、ドラッグで矩形を選ばせる。
静止画の撮影中と録画の範囲の選択中は、新しい撮影や選択を始めない。
遅延がない静止画では、重ね合わせ画面を出す直前の画面を固定して表示し、その上で選ばせる(選んでいる間に画面が変わっても、見えていた内容を撮る)。
遅延がある静止画では、重ね合わせ画面に矩形と操作案内だけを表示し、カウントダウンと選択画面を閉じてから範囲を撮る。
矩形は 1 つのディスプレイの中に収める。
複数ディスプレイにまたがる矩形は、ドラッグを始めたディスプレイの範囲で切り詰める。
Esc か右クリックで取り消す。

**ウィンドウを指定**は、同じ重ね合わせ画面で、カーソルの下にあるトップレベルウィンドウを枠で強調し、クリックで選ばせる。
ウィンドウの範囲は `DWMWA_EXTENDED_FRAME_BOUNDS`(影を除いた見た目の範囲)で決める。
ショートカットキーでは、設定に応じて前面のウィンドウをそのまま撮るか、重ね合わせ画面で選ばせる。
キーを押した時点で前面のウィンドウがない、または撮影できない場合は選択画面を表示する。
遅延の後に対象が閉じられていた場合は、選択画面で選んだときと同じく撮影の失敗として知らせる。
トレイメニューから実行した場合は、常に選択画面を表示する。

プロセスは Per-Monitor V2 の DPI 認識で動かし(`app.manifest` で宣言する)、座標はすべて物理ピクセルで扱う。
選択画面は、ディスプレイごとに 1 枚のフォームを置き、`AutoScaleMode.None` で自前に描く。
全ディスプレイを 1 枚で覆うと、DPI の異なるディスプレイをまたいだときの自動スケーリングで座標がずれるためである。
ウィンドウの候補からは、非表示のもの、最小化されたもの、`DWMWA_CLOAKED` のもの(別の仮想デスクトップにあるウィンドウなど)を除く。

## 静止画

ディスプレイ全体と範囲は、GDI の BitBlt(`CAPTUREBLT` 付き。付けないとレイヤードウィンドウが抜ける)で画面から直接写す。
遅延のない範囲撮影では選択時に固定した画像から切り出し、遅延のある範囲撮影ではカウントダウン後に BitBlt で写す。
ウィンドウを指定した場合は、`GetWindowRect` の大きさで描画先を確保してから `PrintWindow(PW_RENDERFULLCONTENT)` で写し、`DWMWA_EXTENDED_FRAME_BOUNDS` との差分で切り抜く。
通常の `PrintWindow` 経路では、ウィンドウを前面化せず Z 順も変更しない。
結果が全面黒のとき(描画方式によって PrintWindow が内容を返さないアプリがある)は、そのウィンドウを前面に出して BitBlt で撮り直す。
ウィンドウ撮影は 5 秒以内に完了しないと撮影失敗として知らせる。
HDR の表示領域は白く飛び、DRM で保護された動画は黒く写る。これは既知の制約としてマニュアルに書く。
カーソルを写す設定のときは、撮影時点のカーソルを `DrawIconEx` で描き込む。

ファイル名は設定のひな形(「設定画面」の節)から作り、同名があれば `_2`、`_3` を付ける。
動画も同じ規則で名前を付ける。
静止画は同じフォルダーの一時ファイルへ書き終えてから最終名へ改名し、書き込みに失敗した一時ファイルは削除する。
静止画の撮影中にトレイの「終了」を選んだ場合は、撮影と保存が終わってから終了する。
大きな画像のクリップボードへの書き込みは UI スレッドを 1 秒近く止めるため、専用の STA スレッドで行う。
保存に成功したらトレイの通知で知らせ(設定でオフにできる)、通知のクリックで保存先のフォルダを開いてファイルを選択状態にする。

| 設定 | 値 | 既定 |
|---|---|---|
| 形式 | JPEG / PNG | JPEG |
| JPEG の品質 | 1 から 100 | 98 |
| PNG の圧縮 | 速い / 標準 / 最小サイズ | 標準 |
| クリップボードへコピー | オン / オフ | オン |
| カーソルを写す | オン / オフ | オフ |

## 動画

### 映像

ディスプレイ全体と範囲は Desktop Duplication で、ウィンドウは WGC で取る(どちらも ScreenRecorderLib の中で行う)。
ディスプレイ全体と範囲に WGC を使わないのは、検証で WGC が指定のフレームレートを下回ったことと、Windows 10 で WGC が対象に黄色い枠を表示するためである。
ウィンドウは ScreenRecorderLib が WGC しか持たないので、Windows 10 ではウィンドウの録画中だけ対象に黄色い枠が出る(枠は録画には写らない)。
Windows 11 では枠を表示しない設定にする。

範囲、ウィンドウ、縮小後の大きさは、H.264 のエンコーダが受け付けるよう、幅と高さを偶数に切り詰めてからライブラリへ渡す。
エンコーダは「自動」ならハードウェアを優先し、「ソフトウェアのみ」ならハードウェアを使わない設定でライブラリへ渡す。
フレームレートは、「ソフトウェアのみ」ではライブラリの固定フレームレートの設定を有効にして指定する(画面に変化が無い間も、指定の刻みでフレームを書く)。
「自動」では固定フレームレートを使わず、画面に変化があったときだけフレームを書く。
ハードウェアエンコーダ(NVENC で確認)に複製フレームを送り続けると、入力を受け付けない書き込みエラーや、停止時に書き終えの完了が返らない停止が起き、一時ファイルがアプリの終了まで開かれたままになるためである。

ウィンドウの録画中に対象ウィンドウが閉じられたら、アプリが対象の HWND を監視して録画を停止し、そこまでを保存する。
対象ウィンドウの大きさが変わったときと最小化されたときの扱いはライブラリの振る舞いに従い、実測した振る舞いをマニュアルに書く。

| 設定 | 値 | 既定 |
|---|---|---|
| フレームレート | 15 / 24 / 30 / 60 fps | 30 |
| ビットレート | 1 から 100 Mbps | 12 |
| カーソルを写す | オン / オフ | オン |

### 音声

PC の再生音(既定の再生デバイスのループバック)とマイクの取得、両者の混合、映像との同期はライブラリが行う。
音声デバイスの一覧と既定のデバイスの有無は、アプリが Core Audio から直接取得する。ScreenRecorderLib の列挙は既定のデバイスが無いとプロセスごと落ちるためである。
マイクはエンドポイントの ID で保存し、ライブラリへ渡す。
アプリは、どの音源を使うか(PC の音、マイク、マイクのデバイス)と、AAC のビットレートを指定する。
PC の音もマイクもオフのときは、音声トラックの無い MP4 にする。
開始時に指定した再生デバイスまたはマイクが見つからない場合、その音源だけを外して録画し、外した音源を通知する。

録画中に音声デバイスが外れて、ライブラリが失敗のイベントを出したときは、録画を停止してそこまでを保存し、理由を通知する。
デバイスの切り替えの後も録画を続けられるかはライブラリの振る舞い次第なので、確かめられるまではこの扱いにする。

映像と音声の同期は、60 分の録画で音ずれが目で見て分からないことを受け入れの試験で確かめる。
ループバックは再生デバイスを持つ PC でしか確かめられないので、確かめるまでは未検証として扱う。

| 設定 | 値 | 既定 |
|---|---|---|
| PC の音を収録 | オン / オフ | オン |
| マイクを収録 | オン / オフ | オフ |
| マイクのデバイス | 既定のデバイス / 一覧から選ぶ | 既定のデバイス |
| 音声形式 | AAC / MP3 | AAC |
| AAC のビットレート | 96 / 128 / 160 / 192 kbps | 192 |
| MP3 のビットレート | 128 / 192 / 256 / 320 kbps | 192 |

AAC のビットレートの選択肢は、Media Foundation の AAC エンコーダ(ライブラリが内部で使う)が受け付ける値に限る。
マイクの一覧は設定画面を開いたときに取得する。
保存済みのデバイス ID が一覧にない場合も選択肢に残し、ほかの設定を保存したときに ID を失わないようにする。
一覧の取得に失敗した場合は既定のデバイスだけを表示し、選択欄を無効にする。
保存済みの ID がある場合は、選択欄を無効にしている間もその ID を保持する。
MP3 を選ぶと、録画後に変換するため保存に時間がかかることを音声形式の近くに表示する。

### 一時停止、カウントダウン、クリックの強調、縮小

一時停止と再開はライブラリの機能を使う。
出来上がる動画は、一時停止した区間を切り取ってつないだものになる。

ライブラリの初期化中は実際の記録が始まっていないため、準備中は一時停止できない。
利用者が録画開始を認識する時点を、動画への記録が始まる時点にそろえる。

カウントダウンは、対象を選び終えてから録画を始めるまでの間、画面の中央に残り秒数を出す(録画からは除く)。
カウントダウン中に停止のキーを押すと、録画を始めずに取り消す。

クリック位置の強調と出力の縮小は、ライブラリのマウスの設定と出力の大きさの設定を使う。

### 保存の確かさ

MP4 は録画の停止時にファイルの末尾へ索引を書くので、停止の処理が完了しないとファイルは再生できない。
録画中はライブラリに `.recording.mp4` の一時名を渡して書かせ、完了のイベントを受けてから本来の名前へ改名する(MP3 のときは変換を終えてから)。
停止の処理中は操作バーとトレイに「保存中」と表示する。
電源断やプロセスの強制終了では一時ファイルが再生できないまま残る。これは既知の制約としてマニュアルに書く。

録画の開始前に保存先の空き容量を確かめ、1 GB 未満なら開始せずに知らせる。
保存先には UNC パスも指定できる。
開始前の空き容量確認、ファイル名の決定、フォルダーの作成は、ネットワーク上の保存先が応答せず数十秒待つ場合があるため、UI スレッドの外で行う。
録画中にライブラリが失敗のイベントを出したら(ディスクが一杯になった場合など)、録画を停止し、一時ファイルが残っていればその場所を知らせる。
録画エンジンが準備中に 30 秒以内に記録の開始を知らせない場合は開始を諦め、失敗の理由を知らせる。一時ファイルが残っていれば、その場所も知らせる。
停止を要求した後、録画エンジンが例外なく停止を受け付けた場合は、完了または失敗の知らせを 2 分待つ。期限を超えた場合は未完了の一時ファイルを保持し、その場所を知らせる。
開始の通知には約 1.5 秒、停止から完了の通知には約 0.1 秒かかる実測に対し、環境差やファイルの書き込み時間を見込んで上限に余裕を持たせる。
上限を超えた後にライブラリがファイルを書き終えても、一時ファイル(`.recording.mp4`)は最終名へ移さずに残す。次回起動時の未完了ファイルの通知で知らせる。
ライブラリの破棄は録画タスクの取り消し後に完了を待つため、UI スレッドの外で行う。
破棄の中で一時ファイルを書き終えることがあるため、アプリの終了時はトレイを消した後に、破棄の完了を最長 2 分待つ。
録画のカウントダウンから保存完了までは自動スリープを抑止し、スリープ通知を受けたら UI スレッドを待たずに録画エンジンへ停止を要求する。
OS はスリープ前の保存完了を保証しないため、一時ファイルが残る場合がある。

### 録画中の表示

録画エンジンが記録を始めるまでは、画面の端の操作バーに「録画の準備中」と表示し、経過時間を出さない。
この間は一時停止ボタンを無効にし、停止ボタンを有効にする。
記録が始まると経過時間、一時停止ボタン、停止ボタンを持つ操作バーになる。
範囲の録画では、録画範囲の外側に枠を出す。
操作バーと枠は `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` で録画から除く。
トレイアイコンも録画中の見た目に変える(「トレイとショートカットキー」の節)。

録画中に終了や更新を選ばれた場合は、録画を停止して保存してから進む。

## 設定画面

設定画面は次のタブで構成する。
要件の項目に加えて、この種のアプリで使われることの多い機能(遅延撮影、カウントダウン、一時停止、クリック位置の強調、ファイル名のひな形など)を入れる。

**全般**

| 設定 | 値 | 既定 |
|---|---|---|
| サインイン時に起動 | オン / オフ | オン |
| 更新を自動で確認 | オン / オフ | オン |
| 保存完了を通知 | オン / オフ | オン |
| 撮影時に効果音を鳴らす | オン / オフ | オフ |
| ファイル名のひな形 | 文字列(下記) | `ScreenRecorder_{date}_{time}` |
| 月ごとのフォルダに分ける | オン / オフ | オフ |

ファイル名のひな形では、`{date}`(yyyyMMdd)、`{time}`(HHmmss)、`{mode}`(full / region / window)、`{window}`(ウィンドウのタイトル。ファイル名に使えない文字は `_` に置き換え、40 文字で切る)を使える。
ひな形が空か、置き換え後にファイル名として使えない場合は、既定のひな形で保存する。
「月ごとのフォルダに分ける」がオンのときは、保存先の下に `yyyy-MM` のフォルダを作って保存する。

全般タブには、診断ログのグループ(「診断ログ」の節)と、すべての設定を既定に戻すボタンも置く。

**静止画**：保存先、形式、JPEG の品質、PNG の圧縮、クリップボードへコピー、カーソルを写す(各値は「静止画」の節)に加えて、次を置く。

| 設定 | 値 | 既定 |
|---|---|---|
| ウィンドウ撮影のショートカット | アクティブなウィンドウを撮影 / ウィンドウを選択して撮影 | アクティブなウィンドウを撮影 |
| 撮影までの遅延 | なし / 3 / 5 / 10 秒 | なし |
| 撮影後の動作 | 何もしない / 既定のアプリで開く / 保存先を開く | 何もしない |

遅延は、撮影の操作をしてから(範囲やウィンドウを指定する場合は選び終えてから)撮影するまでの待ち時間である(メニューを開いた状態を撮りたい場合に使う)。
範囲撮影で遅延がない場合は選択時の固定画像を使い、遅延がある場合は選択した矩形を待機後に撮る。
待っている間は、残り秒数を画面の端に出す(撮影からは除く)。

**動画**：保存先、フレームレート、ビットレート、カーソル、音声(各値は「動画」の節)に加えて、次を置く。

| 設定 | 値 | 既定 |
|---|---|---|
| 録画開始前のカウントダウン | なし / 3 / 5 秒 | 3 秒 |
| 出力の大きさ | 100% / 75% / 50% | 100% |
| クリック位置を強調する | オン / オフ | オフ |
| エンコーダ | 自動 / ソフトウェアのみ | 自動 |

**ショートカット**：6 つの撮影操作と「録画の一時停止/再開」(既定は割り当てなし)のキー。
入力欄でキーを押すとその組み合わせが入る。
登録に失敗したキーと、ほかの操作と重なったキーには印を付ける。

各行の先頭に「有効」のチェックボックスを置き、操作ごとに機能を無効にできる(既定はすべて有効)。
無効にしても、割り当てたキーは設定に残り、有効に戻せばそのキーで使える。
使わない機能のキーを、ほかのアプリ(Windows の画面切り取りなど)へ譲れるようにするためである。

- 無効にした操作のキーは登録しない。重なりの検査からも外す(登録しないキーは、ほかの操作と重なっても衝突しないため)
- 無効にした行も、キーの入力欄は変更できる。状態の欄には「無効」と出す
- トレイメニューの撮影の項目は、無効なら灰色で押せなくし、ツールチップで「設定のショートカットタブで無効にしています」と理由を示す。静止画か録画の 3 つがすべて無効なら、親の項目も灰色にする
- 「録画の一時停止/再開」は、無効にしてもキーを登録しないだけで、トレイメニューと録画中の操作バーからは一時停止できる。録画中に止められない操作を作らないためである
- 録画中に録画系のキーを押すと停止する規則(「トレイとショートカットキー」の節)は、有効な録画系のキーにだけ当てはまる
- 設定ファイルには、操作ごとの真偽値(`screenshotRegionEnabled` など)で保存する。欠損と不正値は有効として読む

「OK」で保存して即座に反映する(ホットキーの再登録を含む)。
録画中は設定画面の動画タブを変更不可にする。

## 自動起動

`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` に `ScreenRecorder` の名前で exe のパスを書く。
設定がオンのとき、起動のたびに現在の exe のパスで書き直す(zip を別の場所へ展開し直した場合にも追従するため)。
設定をオフにしたら値を消す。

## 更新

### 最新版情報

配布サーバの `https://ktysne.info/screen-recorder/update.json` に最新版の情報を置く。

```json
{
  "schema": 1,
  "latest": {
    "version": "0.2.0",
    "url": "https://ktysne.info/screen-recorder/archives/ScreenRecorder-0.2.0-win-x64.zip",
    "sha256": "<zip の SHA-256 の 16 進 64 文字>",
    "releasedAt": "2026-10-01"
  }
}
```

アプリは次のすべてを満たす場合だけ受け付け、1 つでも外れれば「確認できなかった」として扱う。

- `schema` が整数の 1
- `latest.version` が `X.Y.Z`(各要素は数字だけ)
- `latest.url` が `https://` で始まり、ホストが `ktysne.info` と完全に一致する
- `latest.sha256` が 16 進 64 文字

ホストの比較は、`https://` の直後から最初の `/`、`?`、`#` までを取り出して一字一句比べる。
`https://ktysne.info@example.com/` のように利用者情報を挟む書き方では、実際に接続する先が後ろ側になるためである。
`update.json` と zip の取得では HTTP の転送を自動で追わず、`Location` を現在の URL に対して解決する。
転送先が HTTPS で、ホストが `ktysne.info` と一致するときだけ、最大 5 回まで追う。

### 確認のタイミング

起動の 30 秒後と、その後 24 時間ごとに確認する(設定でオフにできる)。
自動の確認が「確認できなかった」で終わったときだけ、次の確認を 1 時間後にする。起動直後はネットワークにつながっていないことがあり、そのまま 24 時間待つと新しい版の通知が 1 日遅れるためである。
トレイメニューの「更新を確認」からも確認でき、この場合は結果(最新です、確認できませんでした)も知らせる。
自動確認中に手動確認の要求が来た場合は、進行中の確認結果を手動確認として知らせる。

新しい版があれば、トレイの通知と更新ダイアログで知らせる。
自動の確認ではトレイの通知を出し、そのクリックで更新ダイアログを開く。手動の確認では更新ダイアログを直接開く。
自動の確認に失敗したときはログにだけ残す。オフラインの間に通知を繰り返さないためである。
ダイアログの選択肢は「今すぐ更新」「後で」「この版をスキップ」の 3 つとする。
スキップした版は設定に記録し、自動の確認では通知しない(手動の確認では通知する)。
ダイアログには現在の版、新しい版、公開日、ダウンロードの進み具合を出す。
ダウンロードは中止でき、失敗したときは理由と次の行動(もう一度試す、配布ページから zip を入手する)を出す。

### 更新の手順

1. zip を `%LOCALAPPDATA%\ScreenRecorder\update\` へダウンロードし、SHA-256 を `update.json` の値と照合する。一致しなければ中止する
2. zip を同じフォルダの下へ展開し、中に `ScreenRecorder.exe` があることを確かめる
3. 展開した新しい exe を、引数 `--apply-update <旧プロセスの PID> <展開先> <インストール先>` で起動し、旧プロセスは終了する。`--apply-update` の起動は多重起動の判定の対象外にする
4. 新しい exe は旧プロセスの終了を待ち、さらにインストール先の exe と DLL を排他で開けるようになるまで待つ(PID の再利用と、ウイルス対策ソフトによる一時的なロックがあるため。最大 30 秒、再試行付き)
5. 配布物に含まれるファイルごとに、インストール先の同名ファイルを `<名前>.<更新ID>.old` へ改名してから、展開先のファイルをコピーする。更新 ID は更新ごとに生成し、退避先がすでに存在する場合は変更を始める前に中止する。途中で失敗したら、コピーしたファイルを消して、今回退避したファイルを元の名前に戻し、エラーを表示して終わる。既存の `<名前>.old` など、今回の更新で作ったものではないファイルには触れない。フォルダーごと退避しないのは、利用者がそのフォルダーに置いたほかのファイルを巻き込まないためである
6. 旧プロセスのミューテックスが解放されたことを確かめてから、インストール先の exe を `--updated` 付きで起動する
7. 起動した exe は、更新を適用した側の 15 秒後の生存確認が終わるまで待ってから、更新 ID ごとの `cleanup-<更新ID>.json` に記録されたバックアップを片付ける。
   インストール先が一致し、記録の版が実行中の版以下の場合だけ削除する。
   この条件なら後続の更新後も古い記録を処理できる。
   実行中より新しい版の記録は更新が取り消された可能性があるため残す。
   版を読めない記録も残す。
   消せなかったバックアップだけをその記録に残し、すべて削除できた場合は記録ファイルを消す。
   既存の `cleanup.json` も同じ条件で処理する。
   起動の途中で落ちた場合に備え、更新を適用した側は新しいプロセスが生きているかを確かめ、死んでいれば今回のバックアップをすべて戻して旧版を起動する

zip の中の名前がフォルダーの外を指す場合(`..`、絶対パス、ドライブ指定)と、`.old` で終わる名前を含む場合は、展開せずに中止する。
手順 4 と 5 で失敗したときは、ファイルを元に戻したうえで旧版を起動し、理由を表示する。
元に戻せないファイルがあった場合は旧版を起動せず、配布ページの zip を上書きで展開するよう案内する。

更新を適用する側は、実行中を示す名前付きミューテックス(`Local\ScreenRecorder.UpdateApplier`)を終了まで持つ。
また、今回の更新で作った `.old` の一覧を `%LOCALAPPDATA%\ScreenRecorder\update\cleanup-<更新ID>.json` に書く。
更新 ID はバックアップ名と共通にする。
記録ファイルは `ScreenRecorder-*` で始まらない名前にする。
起動した exe はミューテックスの解放を待ってから、`cleanup-*.json` と旧形式の `cleanup.json` をすべて読み、手順 7 の条件で処理する。
15 秒後の生存確認で旧版へ戻すときにバックアップが要るため、適用する側が終わる前には消さない。
この片付けは `--updated` の有無によらず起動のたびに行う。`--updated` は「X.Y.Z に更新しました」の通知だけを加える。

exe のパス(自動起動の登録にも使う)は、起動直後に 1 度だけ取得して保持する。
改名の後にパスを取り直すと `.old` のパスを登録してしまうためである。

exe は .NET のアセンブリを 1 つにまとめた単一ファイルにし、ScreenRecorderLib と VC++ ランタイムの DLL だけを横に置く。
`IncludeNativeLibrariesForSelfExtract` と圧縮は使わない。
起動のたびに一時フォルダへの展開やウイルス対策のスキャンが走って、起動が遅くなるためである。
コード署名はしない。初回の起動で SmartScreen の警告が出ることをマニュアルに書く。

録画中と撮影中は更新を始めない(ダイアログの「今すぐ更新」を、録画と撮影が終わるまで無効にし、その理由をダイアログに出す)。
インストール先へ書き込めない場所(Program Files など)に置かれている場合は、更新を始める前にそれを検出し、zip の手動展開を案内して配布ページを開くボタンを出す。
update.json の取得は 15 秒で打ち切り、キャッシュさせない(`Cache-Control: no-cache, no-store`)。

## 配布

`build-package.bat` のダブルクリックで、次の順に進む。

1. Node.js 22.15 以降があり、`node_modules\basic-ftp` が入っていることを確かめる
2. 版(`X.Y.Z`)を尋ねる
3. 追跡中のファイルに未コミットの変更が無いことを確かめる
4. テストを実行する
5. `dotnet publish` で自己完結の exe を作り、ScreenRecorderLib、VC++ ランタイム、ffmpeg を並べる
6. `index.html`(配布ページ)、`manual.html`(マニュアル)、`license.html`(ライセンス)、`update.json` を生成する
7. `ScreenRecorder-X.Y.Z-win-x64.zip` を作り、その SHA-256 を `update.json` に書く
8. 確認のうえで配布サーバへ転送する。順序は zip、`manual.html`、`license.html`、`index.html`、`update.json` の順で固定する
9. 転送できたら、ビルドしたコミットに `vX.Y.Z` のタグを付けて push する

`update.json` を最後に置くのは、通知を受けた利用者がまだ存在しない zip を取りに行く瞬間を作らないためである。

配布サーバ上の置き場は次のとおり。

- `https://ktysne.info/screen-recorder/`(`index.html`)：配布ページ
- `https://ktysne.info/screen-recorder/manual.html`：マニュアル
- `https://ktysne.info/screen-recorder/license.html`：ライセンス(本体と同梱物のライセンス表記)
- `https://ktysne.info/screen-recorder/update.json`：最新版情報
- `https://ktysne.info/screen-recorder/archives/ScreenRecorder-X.Y.Z-win-x64.zip`：配布 zip

zip の中身は次のとおりとする。

- `ScreenRecorder.exe`
- `ScreenRecorderLib.dll`
- `msvcp140.dll`、`vcruntime140.dll`、`vcruntime140_1.dll`、`concrt140.dll`
- `ffmpeg\`(LGPL の shared ビルドの `ffmpeg.exe` と、それが使う DLL)
- `manual.html`、`license.html`

`build-package.bat` は、publish の出力がこの一覧と一致することを確かめ、想定外のファイル(`.pdb`、`.xml` など)があれば止まる。
VC++ ランタイムの DLL は、ScreenRecorderLib のビルドに使われた版以上のものを、Visual Studio の再頒布用のフォルダーから写す。
ffmpeg は、GPL や nonfree の成分を含まない LGPL の shared ビルドを使い、ビルドの入手元と版、対応するソースの入手先を license.html に書く。
配布の前に、VC++ の再頒布パッケージを入れていない環境(Windows サンドボックスなど)で、起動から録画までができることを確かめる。
マニュアルとライセンスはアプリからも開けるようにする(トレイメニューの「マニュアル」と、設定画面の「ライセンス」)。
開く先は同梱の HTML で、見つからなければ配布サーバの同名のページを開く。

FTPS の接続情報は `tools/deploy.config.json`(Git の管理外)に置く。
雛形は `tools/deploy.config.example.json` である。

## 診断ログ

不具合の原因を後から追えるよう、アプリの中の出来事をこの PC のファイルへ記録する。
ScreenRecorder は利用者の PC で動き、開発者はその環境(ディスプレイの構成、音声デバイス、GPU とエンコーダ、ディスクの速さ)を見られない。
しかもトレイの通知は数秒で消えるので、「録画が保存されなかった」という報告を受けても、直前に何が起きていたのかを知る手立てがない。
利用者の操作に失敗したとき(保存できなかった、エンコーダが使えなかったなど)は、トレイの通知で理由を知らせ、詳細を診断ログに残す。

仕組みと方針は rec-studio の診断ログ(同リポジトリの `docs/12-diagnostic-log.md`)に揃えてある。
違いは、保存先、ファイル名、タグ、記録レベルを変える場所(設定画面の OK で反映する)だけである。

### ポリシー

> **利用者の操作なしに、ログが外へ出ることはない。**

送信の機能を持たない。
ログはこの PC の中のファイルに書かれるだけで、アプリはそれをどこへも送らない(更新の確認は配布サーバから最新版情報を読むだけで、ログを載せない)。
開発者へ渡すかどうかは、利用者がフォルダーを開いてファイルを添付するかどうかで決まる。

記録するのは次のものに限る。

- 利用者の操作と、それによる状態遷移
- エラーと、その理由の文言(ライブラリや OS が返すメッセージを含む)
- ファイル名、フォルダーのパス、撮影する範囲の座標と大きさ、フレームレート、ビットレート、音声の形式
- アプリのバージョンと時刻

記録しないものを明示しておく。

- 撮影した画像、録画した映像と音声そのもの
- クリップボードの中身
- ウィンドウのタイトル
- IP アドレス、利用統計

ユーザー名と PC 名を収集の対象にはしないが、記録するパスには結果としてユーザー名が含まれうる(`C:\Users\<名前>\...`)。
保存先が分からなければ、書き込み失敗の原因を切り分けられないためである。
同じ理由で、ファイル名のひな形に `{window}` を使っている場合は、保存したファイル名にウィンドウのタイトルが含まれる。
渡すかどうかを利用者が決める仕組みにしてあるのは、この点も含めての判断である。
画面のポリシー表示もこの区別のまま書く(「記録しないもの」の一覧へユーザー名を並べない)。

この節が、画面に出すポリシーの文言の正本である。
「診断ログポリシー」のダイアログの説明は、この節を利用者の言葉へ移したものである。
この節を直したら、あちらの文言も見直す。

### 保存先とローテーション

置き場は `%LOCALAPPDATA%\ScreenRecorder\logs\` である。
PC ごとの記録なので、移動プロファイルで持ち回る `%APPDATA%` には置かない。

起動 1 回につきファイル 1 本とし、名前は `screen-recorder-YYYYMMDD-HHMMSS-fff.log` の形にする。
ミリ秒まで入れるのは、終了直後に起動し直しても前回のファイルへ書き足さないためである。
数字を 0 詰めの固定長で並べるので、名前の辞書順がそのまま起動の時刻順になる。
更新の適用(`--apply-update` で起動した別プロセス)も 1 回の起動として 1 本作る。

ローテーションは起動時に 1 回だけ行い、今回作る 1 本を含めて 10 本に収まるよう古いものから消す。
新旧はファイルの更新時刻ではなく名前の順で決める。
更新時刻はコピーや復元で書き換わるためである。
時計が戻って(夏時間の終わりや手動の変更)現在時刻の名前が既存の最新より前になる場合は、最新の名前の 1 ミリ秒後を名前にし、名前の順を起動の順に保つ。
新しいファイルを作ってから古いものを消す。作成に失敗したときに、過去のログだけが減らないためである。

消すのは上の形に厳密に一致し、日時として読める名前だけである。
利用者が `logs\` へ置いたメモや、別のツールが書いたファイルを巻き込まないためである。

記録レベルが「記録しない」のときはファイルを作らず、ローテーションも行わない(前回までのログはそのまま残る)。

### レベル

`silent < error < warn < info < debug` の 5 段で、既定は `info` である。
エラーの 1 行だけでは、その状態へどう到達したかが分からないため、直前の操作が残る `info` を既定にする。

| レベル | 設定ファイルの値 | 設定画面の表示 | 何を記録するか |
|---|---|---|---|
| silent | `silent` | 記録しない | 何も記録しない(ファイルも作らない) |
| error | `error` | エラーのみ | 撮影や録画を続けられない、またはデータを失う恐れのある失敗 |
| warn | `warn` | 警告まで | 異常だが処理は続いた(代わりの経路へ切り替えた、部分的な失敗) |
| info | `info` | 情報まで(既定) | 利用者の操作と状態遷移(連続して起きないもの) |
| debug | `debug` | 詳細 | 連続して起きる追跡(通常は記録しない) |

設定ファイルでは `diagnosticLogLevel` に上の値を書く。
欠損と不正値は既定へ倒す。

計装を足すときは、次の問いで振り分ける。

- **error**：この後も撮影や録画を続けられるか。撮ったものを失う恐れがあるか。
- **warn**：意図した動きではないが、代わりの経路で続けられたか。
- **info**：利用者が起こした 1 回の操作か、その結果としての状態の変化か。
- **debug**：同じ事象が続けて何度も起きるか。

録画中のフレームごとの処理、マウスの移動、カウントダウンの 1 秒ごとの更新のように、操作の量に比例して多発する事象は記録しない。

### タグ

1 行の `[...]` に出る名前で、記録の出どころを表す。

| タグ | 何が書かれているか |
|---|---|
| `app` | 起動、終了、設定の変更、記録レベルの変更、自動起動の登録、未処理の例外、フォルダーやマニュアルを開く操作の失敗 |
| `hotkey` | ショートカットキーの登録の失敗 |
| `capture` | 静止画の撮影の開始、保存、失敗、クリップボードへのコピー、撮影後の動作 |
| `record` | 録画の開始、一時停止、再開、停止、保存、失敗、未完了の録画の保持、対象ウィンドウの消失、スリープによる停止、空き容量の確認 |
| `audio` | 音声デバイスの列挙の失敗、音声の入力元が使えないこと |
| `convert` | MP3 への変換の結果 |
| `update` | 更新の確認の結果、ダウンロード、適用、ロールバック |

### 1 行の書式

```
2026-09-26 14:53:01.123 INFO  [record] 録画を保存した: D:\Videos\ScreenRecorder\ScreenRecorder_20260926_145250.mp4
```

`yyyy-MM-dd HH:mm:ss.fff` の時刻、5 桁で揃えたレベル、角括弧のタグ、メッセージの順に空白で区切る。
専用のビューアを持たない前提なので、メモ帳で読め、`findstr` で絞り込める形にする。
メッセージは日本語で書き、通知の文言と同じ語彙を使う。

1 件を 1 行に保つ。
メッセージの改行、タブ、制御文字は空白へ置き換える(例外のスタックトレースも 1 行に潰す)。
行が崩れると時刻の並びが読めなくなり、絞り込みも効かなくなるためである。

ファイルの先頭には、アプリのバージョン、記録レベル、外へ送られないこと、記録しない内容を数行書く。
利用者が開いて最初に読む行なので、記録レベルの判定を通さずに必ず書く。
文字コードは BOM なしの UTF-8、改行は CRLF にする。

### 書き出しのスレッド

記録する側は、上限つきのキューへ 1 行積むだけで戻る。
ファイルへの書き出しは専用の書き手スレッドが行う。
記録は UI スレッドや録画の停止処理からも呼ばれるので、呼び出し元で書くと、ディスクの応答が遅い環境で操作そのものが止まるためである。

- 書き手は 0.5 秒ごとに目を覚ます。64 件たまったときと error が来たときは、その周期を待たずに起こす。error でも呼び出し元では書かず、待たない
- キューの上限は、通常の記録が 4096 件かつ 1MiB、error はこれと別枠で 64 件かつ 64KiB とする。別枠があれば、多発する記録がキューを埋めた後でも継続不能の記録が入る
- 上限に達したら新しいほうを捨てる。古いほうを捨てると、原因にいちばん近い最初の異常が消えるためである。捨てた件数を数え、次に書けたときに warn で 1 行残す
- 書き出しに失敗したら、その回のぶんは捨てて件数へ数える。書けるまで抱え続けると、失敗を繰り返しながらメモリを食うためである
- 書き出しのたびにファイルを開いて閉じる。開いたままにすると、利用者がエクスプローラーでファイルを扱えないためである
- ローテーションとファイルの作成は、書き手スレッドの最初の仕事にする。作成中にレベルが変わっても 2 本目は作らない
- 終了では残りを書き出してから書き手を止める。待つのは 2 秒までで、過ぎたら書き手を待たずに戻る(書き手はバックグラウンドのスレッドなので、プロセスの終了とともに消える)。記録のためにアプリの終了を止めない
- 未処理の例外で終了する場合も、記録してから同じ上限で書き出しを待つ

書き手が触る状態(キュー、上限のカウンタ、書き出し先)は書き手ごとの塊にまとめる。
待ちが尽きた後に記録を開始し直しても、古い書き手は古い塊しか触らない。

### 設定と取り出し

設定画面の全般タブに「診断ログ」のグループを置き、次の 3 つを並べる。

- 記録レベルの選択欄。直下に、記録はこの PC の中に残るだけで操作なしに外部へ送られないこと、何がどこまで残るかはポリシーで読めることを添える
- 「診断ログのフォルダーを開く」ボタン
- 「診断ログポリシーを確認」ボタン

記録レベルは、ほかの設定と同じく OK で保存して反映する。
レベルを変えたときは、変更そのものを変える前のレベルで 1 行記録する。
「記録しない」や「エラーのみ」へ落とす操作は、落とした後では残せないためである。
変える前のレベルではその 1 行が捨てられる場合(「エラーのみ」から上げた場合など)に限り、新しいレベルで 1 行残す。
この行は info である。どちらのレベルでも info が残らない場合(「エラーのみ」から「記録しない」へ変えた場合など)は残さない。
「記録しない」から他のレベルへ変えたときは、その場でファイルを作る。

「診断ログのフォルダーを開く」は記録レベルにかかわらず押せる。
「記録しない」でも前回までのログはフォルダーに残っているためである。
押したら、溜めてある行の書き出しを 0.3 秒まで待ってからフォルダーをエクスプローラーで開く。
フォルダーがまだ無ければ作ってから開く。

「診断ログポリシーを確認」は、設定画面を親にしたモーダルのダイアログを開く。
先頭に「あなたの操作なしに、ログが外へ出ることはありません。」を太字で置き、その下に、保存される場所、記録レベルごとに残るもの、記録しないもの、記録するもの、ファイル名とパスの扱いを見出しつきで並べる。
本文は読み取り専用で、選択してコピーできる。

設定画面を開いた操作とポリシーを表示した操作は記録しない。
ログの設定を見に来た操作でログが埋まるためである。

アプリの中にログのビューアと削除の操作は持たない。
エクスプローラーとテキストエディタで読め、添付でき、削除もできるうえ、10 本を超えた分は起動のたびに消えるためである。

### 層とテスト

レベル、設定値の名前、1 行の書式、文字の置き換え、ファイル名、ローテーションの選別、書き手スレッドとキューは Core に置く。
書き出し先は差し替えられる形にし、遅延と失敗を注入した書き出し先でキューと書き手のふるまいをテストする。
記録の呼び出し口はプロセスに 1 つだけ持ち、App の各所から直接呼ぶ。
実際のファイルの削除、設定画面とダイアログは実機で確かめる。

## マニュアルとライセンスの生成

マニュアルの原稿は `site/manual.template.html`、ライセンスの原稿は `site/license.template.html`、配布ページの原稿は `site/index.template.html` に置き、`tools/release-site.js` が版を埋め込んで出力する。
配布ページが載せるアプリのアイコンは `site/assets/app-icon-256.png` に置き、`tools/release-site.js` がページと一緒に出力先の `assets/` へ写して公開する。
UI の文言は `src/ScreenRecorder.App/UiLabels.cs` に集め、マニュアルが参照するメニュー名とボタン名がそこに実在するかを `tools/check-manual-labels.js` で検査する。
`build-package.bat` はビルドの前にこの検査を行い、食い違いがあれば止まる。
マニュアルに書いた操作が UI に無いと、利用者は手順どおりに操作できないためである。

ライセンスページには、ScreenRecorder 本体と ScreenRecorderLib のライセンス(どちらも MIT)の全文を載せ、.NET ランタイム、VC++ ランタイム、ffmpeg(と、ffmpeg に含まれる libmp3lame などの LGPL の成分)は、ライセンスの種類と正本へのリンクを載せる。
ffmpeg については、同梱のビルドの `ffmpeg -version` の出力(版と構成)を `build-package.bat` が差し込み、LGPL の全文は `ffmpeg\` に同梱するライセンスの文書で示す。
`tools/release-site.js` は、構成に `--enable-gpl` か `--enable-nonfree` を含むビルドを見つけたら生成を止める。
ffmpeg については、動的リンクで使っていることと、対応するソースの入手先も書く。
