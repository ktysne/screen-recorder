# MCP のサーバー

状態：設計済み(未着手)

この資料は、自動化用 CLI を MCP のサーバーとして動かす仕組み(段階 5)の形と安全性を定める。
CLI 全体の約束と段階の位置づけは [automation-cli.md](automation-cli.md) にあり、この資料はその「段階 5」を詳しくしたものである。
常駐中の本体の操作は [automation-remote.md](automation-remote.md) で定めた `remote` のコマンドをそのまま使う。

## 目的と範囲

シェルを持たない MCP のクライアント(Claude Desktop など)から、撮影、録画、動画と画像の検査、常駐中の本体の操作を頼めるようにする。
開発の場面ではシェルから CLI を直接呼べるので、MCP は使わない。

範囲に含めるもの：

- `screenrecorder-cli mcp` のサブコマンド。標準入出力で動く MCP のサーバーにする。
- 道具(tool)の一覧と入力のスキーマを、CLI のコマンドの定義の表から作る仕組み。
- 書き込み先と実行ファイルの制限、呼び出しの直列化、取り消し、進捗の通知。

範囲に含めないもの：

- 撮影した画像を画像の内容(image content)として返すこと。効果は大きいが、大きさの上限と縮小の扱いを別に決める必要があるので、後の段階で扱う。
- リソース(resource)とプロンプト(prompt)。道具だけで目的を満たせるためである。
- CLI の配布。[automation-cli.md](automation-cli.md)「配布」のとおり、当面は手元のビルドで使う。

## 実装の形

公式の C# SDK のうち、ホスティングと DI を含まない `ModelContextProtocol.Core` を使う。
版は完全に固定する(`2.2.0`)。

SDK を使うのは、初期化での版の交渉、道具の注記、進捗と取り消しの通知を自前で追い続けずに済むためである。
録画プロセスや常駐中の本体との通信は JSON-RPC ではない独自の形なので、流用できない。

道具の一覧を作る処理と、道具の入力から CLI の引数を組み立てる処理は、SDK の型に依存しないクラスに置く。
SDK とつなぐのは、道具の一覧と呼び出しを受ける 2 つの処理(`ListToolsHandler` と `CallToolHandler`)だけにする。
SDK の API が変わっても、直す場所をここに閉じ込めるためである。

道具の呼び出しは、組み立てた引数で CLI の入口(`CliApplication.Run`)を呼び、標準出力に書かれた JSON をそのまま text の内容として返す。
終了コードが 0 以外なら `isError` を true にする。JSON の `error.code` はそのまま残し、MCP の側で包み直さない。
CLI の出力の約束([automation-cli.md](automation-cli.md)「出力」)を、MCP でも同じ形で読めるようにするためである。

呼び出しごとに CLI の環境(`CliEnvironment`)を作り直す。設定の保存先などが、サーバーの起動後に変わりうるためである。

## 道具の一覧

CLI のコマンドの定義の表から、`help` と `mcp` を除いたすべてのコマンドを道具にする。
表と別に道具を手で書くと、CLI にコマンドを足したときに MCP の側が取り残されるためである。

### 名前とスキーマ

- 道具の名前は、コマンド名の空白を `_` にしたもの(`remote status` は `remote_status`)。
- 入力のプロパティの名前は snake_case にする(`--capture-after` は `capture_after`)。`-o` のような短い名前は、表で明示的に `output` と対応づける。先頭の `-` を除くだけの一般の規則にはしない。
- 値を取らないオプションは boolean にする。
- 値を取るオプションには、定義の表に値の種類(文字列、整数、数、列挙、パス)を持たせ、スキーマの型に写す。`--state`、`--mode`、`--level`、`--log-level` は列挙、秒や番号は整数か数にする。すべて文字列にすると、AI が `"3"` と `"3s"` を混ぜるためである。
- 位置引数には、定義の表に英語の名前を 1 つ足し(`remote perform` は `action`、`probe` と `logs show` は `file`)、そのプロパティにする。必須の位置引数は `required` に載せる。
- 「`--display`、`--rect`、`--window` のどれか 1 つ」のようにスキーマで表せない条件は、道具の説明に書く。

### 道具から外すオプション

- 共通の `--text`：MCP の出力は JSON に固定する。
- `--app`(`record` と `remote` の各コマンド)：MCP のサーバーの起動時に `mcp --app <パス>` で決め、道具の入力から外す(「安全性」)。

### 説明と注記の上書き

コマンドの説明は CLI の `help` と同じ文言を使い、MCP だけに要る説明と注記を上書きの表で足す。

| 道具 | 注記 | 足す説明 |
|---|---|---|
| `info`、`settings_*`、`logs_*`、`remote_status`、`remote_wait`、`naming_preview` | 読み取りだけ | `naming_preview` には「開発向け」と書く |
| `probe` | `output` を指定しなければ読み取りだけ | なし |
| `record` | 書き込みあり | 呼び出しが録画の長さの間終わらないこと。長い録画は `remote_perform` と `remote_wait` で本体に録らせること |
| `screenshot` | 書き込みあり | なし |
| `remote_perform`、`remote_select` | 本体を操作する | なし |
| `remote_exit` | 本体を終了する(破壊的) | なし |

`force` を持つ道具は、上書きがありうるので破壊的の注記も付ける。

## 呼び出しの直列化

道具の呼び出しは、1 本の専用のスレッドで 1 つずつ実行する。
診断ログの転送先が static で、`record` と `screenshot` は画面を使うので、同時に走らせられないためである。
このスレッドは STA にする。CLI の入口は `[STAThread]` の Main から呼ばれる前提で作られているためである。

SDK は呼び出しを並行して渡してくるので、実行中に届いた呼び出しは数秒だけ待ち、空かなければ `busy` の `isError` で返す。
待たせ続けても、クライアントの時間切れで失敗するだけだからである。

## 時間切れと進捗

クライアントは呼び出しごとに時間切れを持ち、その長さはサーバーから決められない。
このため、MCP から呼ぶときは `record` の `--duration` と `remote wait` の `--timeout` を 60 秒までに限り、超える依頼は「`remote_perform` と `remote_wait` で本体に録らせる」と案内するエラーで断る。

呼び出しに進捗の印(`progressToken`)があれば、`record` は録画中に 1 秒ごとに進捗を通知する。
クライアントは進捗を受けて時間切れを延ばしてよいと MCP の仕様が定めているためである。

## 取り消しと終了

クライアントが呼び出しを取り消したら、実行中のコマンドを止める。
`record` は今は Ctrl+C(`Console.CancelKeyPress`)だけを見ているので、止める経路を取り消しの印(`CancellationToken`)からも呼べるようにする。
取り消しを無視すると、録画プロセスが録画を続け、ファイルを書き続けるためである。

標準入力が閉じたら(クライアントの終了)、実行中のコマンドを同じ経路で止めてから終了する。

## 標準出力の保護

標準出力は MCP の通信だけに使う。1 行でも別の文字が混ざると、クライアントが通信を読めなくなるためである。

- `mcp` の分岐は CLI の入口より前(`Program`)で行い、分岐の直後に `Console.SetOut` を標準エラーへ向ける。SDK の標準入出力の転送は、標準出力のストリームを直接開くので影響を受けない。
- 道具の呼び出しでは、CLI の入口に渡す標準出力の書き手を、呼び出しごとの `StringWriter` にする。`Console.Out` を渡さない。
- 録画プロセスと ffmpeg の子プロセスは、標準出力を親から受け継がないよう `RedirectStandardOutput` を有効にして読み捨てる。受け継ぐと、子プロセスの出力が通信路に混ざるためである。この変更は `mcp` 以外の実行にも害がないので、常に行う。
- SDK にロガーを渡すときは、標準エラーに書くものだけにする。コンソール用の既定のロガーは標準出力に書くためである。

## 安全性

MCP のクライアントへ渡る道具の入力は、画面や診断ログの内容から AI が組み立てることがある。
画面に映った文やログの行に紛れた指示で、意図しない操作が起きうる前提で、次を制限する。

- 実行ファイル：`record` と `remote` の接続先の照合に使う本体の場所は、`mcp --app <パス>` で起動時に決める。省略したときは、CLI と同じフォルダーの `ScreenRecorder.exe` を使う。道具の入力から任意の実行ファイルを起動させないためである。
- 書き込み先：`output` は絶対パスで、許可したフォルダーの下に限る。許可するのは、一時フォルダー(`%TEMP%`)と、`mcp --allow-dir <フォルダー>` で足したフォルダーである。相対パスは断る。Claude Desktop などが MCP のサーバーを起動するときの作業フォルダーは決まっていないためである。
- 設定ファイル：`record` と `screenshot` の `settings` は、ffmpeg の場所を含む設定を読んで実行に使うので、書き込み先と同じ制限をかける。`settings_validate` と `settings_show` の `file` は読んで検査するだけなので制限しない。
- 断ったときは、`error.code` を `pathNotAllowed` にした JSON を `isError` で返す。終了コードの考え方は引数の誤りと同じ 2 とする。

常駐中の本体の操作(`remote_perform`、`remote_exit` など)は、本体の設定「自動化用の接続を受け付ける」がオンのときだけ働く。
この制限は [automation-remote.md](automation-remote.md)「有効にする条件」のとおりで、MCP の側では足さない。

## 登録の方法

[development.md](development.md) に、Claude Desktop の設定ファイルへの登録の例を書く。
例は、`dotnet build ScreenRecorder.slnx` で作った `screenrecorder-cli.exe` を指し、`mcp --app` に同じビルドの `ScreenRecorder.exe` を渡す形にする。

## テスト

`tests/ScreenRecorder.Cli.Tests` で、プロセスを起動せずに確かめる。

- 道具の一覧が、コマンドの定義の表(`help` と `mcp` を除く)と過不足なく一致すること。スキーマの型、`required`、注記。
- 道具の入力から CLI の引数への変換。列挙の値、boolean、位置引数、外したオプションを渡したときの誤り。
- 書き込み先の制限。許可したフォルダーの下、外、相対パス、`..` を含むパス。
- 60 秒を超える `duration` と `timeout` を断ること。
- SDK のストリームの転送を 2 つのパイプでつなぎ、初期化、`tools/list`、`tools/call`(`info`)を 1 往復すること。
- 実行中に届いた 2 本目の呼び出しが `busy` で返ること。取り消しで実行中のコマンドが止まること。

## 決めていないこと

- 撮影した画像を画像の内容として返すか。返すなら、大きさの上限と縮小の方法。
- 許可するフォルダーに、本体の設定の保存先(静止画と動画)を既定で含めるか。含めれば利用者の手間は減るが、AI が利用者の保存先を上書きできるようになる。
